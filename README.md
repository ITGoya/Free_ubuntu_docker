# 🖥️ Ubuntu Desktop in Docker (noVNC + SSH) — دسکتاپ اوبونتو داکری با دسترسی وب و SSH

این پروژه یک **کانتینر داکر شامل دسکتاپ گرافیکی کامل اوبونتو (XFCE)** می‌سازه که از دو طریق قابل دسترسیه:

- 🌐 از طریق **مرورگر** (noVNC) — بدون نیاز به نصب هیچ برنامه‌ای
- 💻 از طریق **SSH** (با PuTTY، Bitvise یا هر کلاینت SSH دیگه)

برای اجرا روی پلتفرم‌هایی مثل [Railway](https://railway.app) طراحی شده، ولی روی هر سرویس Docker دیگه‌ای هم قابل اجراست.

---

## 📦 این پروژه چیکار می‌کنه؟

`Dockerfile` این کارها رو انجام می‌ده:

| مرحله | توضیح |
|---|---|
| 1 | یک ایمیج بر پایه‌ی `ubuntu:22.04` می‌سازه |
| 2 | محیط دسکتاپ سبک **XFCE** رو نصب می‌کنه |
| 3 | سرور **VNC** (`tigervnc`) رو برای دسترسی به دسکتاپ راه‌اندازی می‌کنه |
| 4 | با **noVNC + websockify** همون VNC رو از طریق مرورگر (HTTPS) در دسترس می‌ذاره |
| 5 | سرور **OpenSSH** رو نصب و پیکربندی می‌کنه تا با PuTTY/SSH هم بشه وصل شد |
| 6 | مرورگر **Firefox** (نسخه‌ی deb، نه snap) رو نصب می‌کنه |
| 7 | آیکون‌ست **Xubuntu** رو برای ظاهر بهتر اضافه می‌کنه |

---

## 🚀 راه‌اندازی روی Railway

1. این ریپازیتوری رو **Fork** کن.
2. یک پروژه‌ی جدید در Railway بساز و همین ریپازیتوری فورک‌شده رو بهش وصل کن.
3. Railway به‌صورت خودکار از روی `Dockerfile` بیلد و دیپلوی می‌کنه.
4. برای دسترسی از طریق مرورگر (noVNC)، در تب **Settings → Networking** روی سرویس، دکمه‌ی **Generate Domain** رو بزن و پورت داخلی رو `6080` بذار.
5. برای دسترسی از طریق SSH، دکمه‌ی **TCP Proxy** رو بزن و پورت داخلی رو `22` بذار — Railway یک هاست‌نیم و پورت خارجی بهت می‌ده.

---

## 🔑 تنظیم رمز عبور SSH (خیلی مهم)

رمز عبور کاربر `root` **داخل کد نوشته نشده** و از طریق یک متغیر محیطی تنظیم می‌شه:

1. در پنل Railway، روی سرویست، برو به تب **Variables**.
2. یک متغیر جدید با این مشخصات بساز:

   ```
   SSH_PASSWORD = یک-پسورد-قوی-و-دلخواه-خودت
   ```

3. بعد از ذخیره، Railway خودکار یک دیپلوی جدید می‌زنه و پسورد `root` همون چیزی می‌شه که تعیین کردی.

> ⚠️ اگه این متغیر رو تنظیم نکنی، پسورد پیش‌فرض `changeme123` فعال می‌مونه که **اصلاً امن نیست**. حتماً قبل از استفاده‌ی واقعی، این متغیر رو با یک پسورد قوی تنظیم کن.

## 🌐 دسترسی به دسکتاپ گرافیکی (noVNC)

بعد از ساخت دامنه (مرحله ۴ بالا)، دامنه‌ای که Railway می‌ده رو در مرورگر باز کن. چون سرور VNC **بدون پسورد** پیکربندی شده، مستقیم وارد دسکتاپ می‌شی.

## 🔐 دسترسی با SSH

با هر کلاینت SSH (PuTTY، Bitvise، ترمینال لینوکس/مک و...) به این مشخصات وصل شو:

- **Host:** هاست‌نیمی که Railway برای TCP Proxy داد (مثلاً `xxxxx.proxy.rlwy.net`)
- **Port:** پورت خارجی TCP Proxy (نه ۲۲؛ عددی که Railway نشون می‌ده)
- **Username:** `root`
- **Password:** همونی که در `SSH_PASSWORD` تنظیم کردی

## ⚠️ هشدارهای امنیتی

این پروژه برای **تست، یادگیری و استفاده‌ی شخصی/موقت** طراحی شده، نه محیط پروداکشن یا عمومی:

- سرور VNC **بدون هیچ پسوردی** اجرا می‌شه (`SecurityTypes None`) — هرکسی که آدرس noVNC رو داشته باشه، مستقیم به دسکتاپ دسترسی داره.
- لاگین **root با پسورد** برای SSH فعاله؛ برای امنیت بیشتر می‌تونی به احراز هویت با کلید SSH سوییچ کنی و `PasswordAuthentication` رو غیرفعال کنی.
- گواهی SSL که برای HTTPS استفاده می‌شه **self-signed** هست، پس مرورگر هشدار امنیتی نشون می‌ده (طبیعیه).
- هیچ فایروال یا محدودیت IP روی این تنظیمات اعمال نشده.

**پیشنهاد:** این کانتینر رو فقط برای بازه‌های زمانی کوتاه و کارهای موقت (تست، دمو، دسترسی سریع به یک محیط گرافیکی لینوکسی) نگه دار، نه به‌عنوان سرور دائمی.

## 📋 منابع (Resources)

منابعی که پلتفرم به این کانتینر اختصاص می‌ده، معمولاً با آنچه دستورات معمولی لینوکس (`nproc`, `free -h`, `df -h`) نشون می‌دن فرق داره، چون اونا سطح ماشین میزبان اشتراکی رو گزارش می‌کنن. برای دیدن سهم واقعی:

```bash
nproc                              # هسته‌های قابل‌مشاهده (ممکنه گمراه‌کننده باشه)
cat /sys/fs/cgroup/cpu.max         # سهم واقعی CPU
cat /sys/fs/cgroup/memory.max      # سهم واقعی RAM (بایت)
df -h /                            # فضای دیسک (اشتراکی با میزبان)
```
